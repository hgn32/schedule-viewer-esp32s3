# プロジェクト開発ルール

## 0. 禁止事項（絶対厳守 / 最優先）

## 1. 全体原則

- 回答はすべて**日本語**で行ってください。
- 常にシニアエンジニアとして、丁寧かつ簡潔に回答してください。

## 2. 開発プロセス（必須ステップ）

新しい機能の実装や大きな修正を行う際は、必ず以下の3ステップを順に踏んでください。

### ステップ1:ブレインストーミング(`superpowers:brainstorming`)

- 実装を始める前に、要件の意図や背景を確認してください。
- 技術的な選択肢（メリット・デメリット）を提示し、影響範囲を洗い出してください。
- ユーザーから実装方針の合意を得るまで、コード生成は開始しないでください。
- 不明点は必ず確認してください。仮定で進めてはなりません。
- 積極的に機能の改善案やリスク回避策も提案してください。

### ステップ2:計画作成(`superpowers:writing-plans`)

- 合意した方針に基づき、詳細な実装計画を作成してください。
- 変更が必要なファイル、手順、依存関係を箇条書きで示してください。
- 可能であれば、コードの構造や関数の概要も説明してください。
- 図を用いて説明することも有効です。必要に応じて、コードスニペットを使って具体例を示してください。

### ステップ3:実装(`superpowers:subagent-driven-development`)

- 作成した計画に基づき、コードを生成・修正してください。
- 可能な限り、テストコードの作成や既存テストの実行も含めてください。
- 変更内容をコミットする前に、コードレビューの観点で自己チェックを行ってください。

## 3. 作業前の変更提案（絶対厳守）

いかなる実装・修正・削除作業を行う前にも、必ず以下を提示してユーザーの承認を得ること。承認前にファイルを編集してはならない。

- **変更対象ファイル**:変更するファイルの一覧
- **変更概要**:各ファイルに対して何を追加・変更・削除するかの箇条書き
- **影響範囲**:変更によって影響を受ける可能性のある他のコンポーネントや機能

ユーザーが「OK」「進めて」「実装して」などの承認を明示した後にのみ、実装を開始すること。

## 4. 編集後の必須確認（絶対厳守）

コード変更後は必ず以下を実行し、エラーがないことを確認すること。

### 4-1. ビルド

devcontainer内で実行する。非対話シェルは`PATH`に`idf.py`が無いのでexport.shの読み込みが必須。

```bash
cd /workspaces
. /opt/esp/idf/export.sh >/dev/null 2>&1
idf.py build
```

- 初回のみ`idf.py set-target esp32`が必要（devcontainerの`postCreateCommand`で自動実行される）。
- 警告が新たに増えた場合も原因を報告すること。

### 4-2. テスト

- 自動テストは現状このrepoに存在しない。外部依存の無い純粋なロジック
  （`main/protocol.cpp` / `main/schedule.cpp` / `main/time_util.h`）の検証が必要になったら、
  ESP-IDFのUnityを導入することをまず提案すること。勝手に導入しない。

### 4-3. 実行時のルール

- `idf.py flash` / `idf.py monitor`は実機と`/dev/ttyUSB0`が必要なため、エージェントが勝手に実行しない。
  実機確認が必要なときはユーザーに依頼すること。
- ビルドが失敗した場合は、原因を特定して修正するか、修正できない場合は失敗内容をそのまま報告すること。
  警告抑制やコードの削除で「通ったことに」してはならない。
- 確認せずに完了報告をしてはならない。結果（成否・警告の増減）を報告に含めること。

## 5. 技術スタック & コーディング規約

- ターゲット: Waveshare ESP32-S3-Touch-LCD-7B（ESP32-S3-WROOM-1-N16R8 / Xtensa LX7、16MBフラッシュ、8MB Octal PSRAM、1024x600 RGB LCD）
- 言語: C++（`app_main()`は`extern "C"`）
- フレームワーク: ESP-IDF v5.5 + `esp_lcd`(RGBパネル) + LovyanGFX 1.2.28（git依存） + `espressif/freetype`
- 命名規則: 変数・関数はcamelCase、クラス・型はPascalCase、定数・マクロはUPPER_SNAKE_CASE
- **`.cpp` / `.h`を編集する前に、必ず`CLAUDE.md`の「C++ファイル編集時のルール」と
  「実装上の決定事項」を読み、全ルールを遵守すること。**
